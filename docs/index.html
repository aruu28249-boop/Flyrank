Content Opportunity Scoring for Search Intelligence

A baseline system for prioritizing content pages for human review using observed Google Search performance signals.

Abstract

This project asks which content pages should be prioritized for review or refresh based on their observed Google Search performance. The analysis uses the FlyRank Internship Warehouse and focuses on the March 2026 data slice. A simple baseline score combines observed search impressions and average search position to create a ranked recommendation queue. The resulting system assigns each row a priority score, reason code, and action label. The result is intended as directional decision-support for human review rather than causal evidence that refreshing a page will improve search performance.

1. Introduction / Problem Statement

Content teams may have many pages that could potentially deserve attention, but human review time is limited. This project supports the decision of which pages should be inspected first.

The research question is:

Which content pages should be prioritized for review or refresh based on their observed Google Search performance?

The goal is not to automatically decide that a page should be refreshed. Instead, the system creates a ranked queue that helps a human reviewer decide where to look first.

2. Data

This project uses the FlyRank Internship Warehouse dataset released through Hugging Face. The primary table is fact_content_daily_performance.

The analysis uses March 2026 as the development window. The data contains one row per report date, pseudonymized client, and pseudonymized content item.

Observed signals

  • gsc_impressions
  • gsc_clicks
  • gsc_avg_position

Future outcome information, label-derived fields, client-identifying information, and other information that could introduce target leakage were excluded.

3. Methodology

Baseline approach

The baseline uses observed search performance to calculate a priority score. Higher search impressions represent greater observed search demand, while a higher average position number represents more room for potential improvement under this baseline framing.

The baseline score is:

priority score = impressions × average position

Reason codes

Reason code Action
HIGH_DEMAND_OPPORTUNITY REVIEW_FOR_REFRESH
LOW_DEMAND LOW_PRIORITY
STRONG_POSITION MONITOR

The ranking uses only observed March 2026 signals. No future-window or label-derived inputs are used in the baseline.

4. Results

The baseline produces a ranked queue of content recommendations. Each recommendation contains a priority score, reason code, and action label.

The March 2026 development slice contains 9,841,378 rows, covering March 1 through March 31, 2026.

The baseline is intended to serve as the reference system against which a future machine learning model can be evaluated on the same validation design.

5. Limitations

This project provides a simple baseline ranking system using observed Google Search performance signals. It should not be interpreted as proof that refreshing a page will improve rankings or traffic.

  • It uses only a small set of observed search signals.
  • It does not consider content quality, search intent, backlinks, or technical SEO factors.
  • The same content page may appear multiple times because the ranking is based on daily observations.
  • The results are observational and cannot establish cause-and-effect relationships.
  • The baseline should be validated against a future evaluation period and compared with stronger machine learning models.

The recommendations should therefore be treated as directional decision-support, not final business decisions.

6. Ranked Recommendations

The baseline creates an ordered queue for human review. Pages receiving the REVIEW_FOR_REFRESH action are candidates for further manual inspection.

Pages marked MONITOR have stronger observed positions under the baseline and should generally be monitored rather than immediately refreshed.

Pages marked LOW_PRIORITY have limited observed search demand and are lower-priority candidates for review.

These labels are recommendations for inspection, not automatic decisions.

7. Reproducibility

The analysis is implemented in the project repository under work/notebooks/.

The main capstone notebook contains the research question, data description, methodology, baseline results, limitations, ranked recommendations, and artifact generation.

The baseline queue is generated from the notebook rather than relying on a manually edited result.
